calc-per-cohort branch — PIT-safe calculator
================================================

目標：解掉 PIT leak 其中一條（calculator 衍生表 DROP+replace 造成歷史
row drift）。step1 SQL 的 publish_time 過濾另開 branch 處理。

預期成效：消除 calculator 端造成的 backtest drift（valuation_daily 的
pe_percentile_official rank 重分配）。剩下的 raw-table late-publish drift
（~60% 主因）等下一個 branch 修。

---------------------------------------------

共通改法（已套用）：
  1. 啟動先 `SELECT MAX(date) FROM <table>` 取 last_processed
  2. raw 表 SELECT 限制 `WHERE date > last_processed`（concentration WoW
     用 date >= last 拿 1 個前 snapshot；calculate_daily MA240 用 500 天 buffer）
  3. INSERT 新 row，PRIMARY KEY (date, symbol) 防重；DELETE+INSERT 同
     區間以支援 re-run
  4. 砍掉 DROP TABLE / if_exists='replace'
  5. 加 --force-full 旗標
  6. 共用 helper：calculator/_incremental.py（get_engine /
     get_last_processed_date / table_exists / parse_force_full）

Phase 2 — pe_percentile_official 一次性 PIT backfill  [✅ DONE]
----------------------------------------------------

[x] calculate_valuation.py incremental 邏輯改成 expanding rank
    (add_pit_expanding_rank：concat 歷史 PE + 新 PE → groupby(symbol)
     .expanding().rank(pct=True) → 取新 row 那部分)
[x] calculator/backfill_pit_percentile.py（一次性 migration）
    - 載入 1.47M rows
    - groupby(symbol).expanding().rank(pct=True) 計算 PIT percentile
    - 寫 temp table → bulk UPDATE
    - 處理 valuation_daily 的 3 個 (symbol, date) duplicate（pe_official
      上游兩筆，pe_calculated 同 → percentile 同，dedupe 後 UPDATE）

驗證結果：
[x] backfill 前 avg(pe_percentile_official) = 50.05（leaky full-history）
    後 avg = 51.87（expanding rank，有 mild 上偏因早期樣本小，符合預期）
[x] spot check 3-5 個 symbol 最早幾筆：早期 row 多為 100 或 50（樣本 1-2 個）
